# 網頁回報板（問題回報與建議）

使用者確認：2026-11-02（採 A 做法：網頁直接讀寫遊戲裡的留言板；只開放已登入角色；一個版「問題回報與建議」）。

## 玩家看到的

- 左側選單「回報」按鈕；有未讀文章時按鈕右邊出現紅色數字（每分鐘查一次）。
- 按下打開可拖曳、可縮放的「問題回報與建議」視窗：
  - **列表**：全部／回報／建議／只看未讀；每篇一行（編號、類別、標題、作者、日期），最新的在最上面，未讀標題是黃色。
  - **閱讀**：點標題看全文；較新／較舊切換；回覆；自己的文章（或巫師）可刪除。
  - **發文**：選類別（回報、建議），填標題與內容，按送出。發文者就是登入中的角色。
  - **回覆**：自動帶「Re﹕」標題，引用原文開頭（最多 6 行、約 200 字）。
- 沒登入角色時只會看到「登入角色後才能使用回報板。」

## 規則

| 項目 | 設定 |
|---|---|
| 留言板 | `/daemon/board/bug_board`（雪亭回報小廣場那塊），改名「問題回報與建議留言板」 |
| 篇數上限 | 100 篇；超過時照原本規則一次清掉最舊的四分之一 |
| 標題 | 網頁 20 字以內（回覆加「Re﹕」後最多 24 字）；存檔時前面加【回報】或【建議】 |
| 內容 | 1000 字以內 |
| 刪除 | 自己的文章；巫師（權限 4 以上）可刪任何文章——同遊戲裡 `discard` |
| 已讀紀錄 | 跟遊戲裡共用（記在角色連線資料的 `board_read/bugs`） |

遊戲裡走到回報小廣場用 `read`、`post` 也看得到、寫得到同一批文章。
遊戲裡發文的標題長度仍照原本留言板的限制，沒有類別標籤。

## 技術做法

- 網頁把請求排隊，跟著背景狀態查詢一起送：`webhud board <動作> <請求代號> …`。
  `cmds/usr/webhud.c` 把它交給 `daemon/misc/web_board.c`，結果用 `@@WEBHUD|BOARDBEGIN／BNOTE／BREAD／BOARDEND` 資料行回傳，玩家畫面看不到。
- 動作：`count`、`list`、`read <編號> <時間>`、`chunk <序號> <內容>`、`post <bug|idea> <標題>`、`del <編號> <時間>`。
  以「編號＋時間」找文章，別人剛刪文造成編號移動時不會讀錯、刪錯。
- 遊戲每行輸入最多 2048 位元組，所以內容分段（每段 ≤1200 位元組）先存在角色暫存，再用 `post` 發出。
- 標題、內容的跳脫：`\\` 反斜線、`\n` 換行、`\s` 空白（整段是一行，前後空白也不會被吃掉）；回傳內文另把 `|` 跳成 `\p`。
- 遊戲每秒指令數有上限（`webhud` 本身不算，帶留言板請求的會算）：網頁讓請求間隔至少 0.4 秒；
  若仍被擋（回覆「你下指令的速度太快了」）就等 2 秒自動重送，最多兩次。
- 程式：`web/board.js`（視窗）、`web/app.js`（排隊與送出）、`cmds/usr/webhud.c`、`daemon/misc/web_board.c`、`daemon/board/bug_board.c`。

## 更新方式

不需要重開。拉程式後巫師在遊戲裡 `update /cmds/usr/webhud`、`update /daemon/board/bug_board`
（`daemon/misc/web_board.c` 第一次用到時才載入）；玩家按 F5。
